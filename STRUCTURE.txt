# CORE DATA STRUCTURES
Device = {
    "id": UUID,
    "name": str,           # e.g., "Lab Router 1"
    "ip_address": str,     # e.g., "192.168.1.1"
    "hostname": str,       # e.g., "router-lab-01"
    "device_type": str,    # "router" | "switch" | "server" | "printer"
    "location": str,       # e.g., "Building A, Floor 2"
    "is_active": bool,     # whether to monitor this device
    "created_at": datetime
}

MonitoringConfig = {
    "device_id": UUID,
    "ping_interval_sec": int,      # default: 60
    "timeout_sec": float,          # default: 2.0
    "retry_count": int,            # default: 3
    "latency_threshold_ms": int,   # default: 100
    "consecutive_failures": int    # default: 2 (before alerting)
}

AlertRule = {
    "id": UUID,
    "device_id": UUID,      # or "ALL" for global rules
    "alert_type": str,      # "email" | "sms" | "webhook" | "dashboard"
    "recipient": str,       # email address or phone number
    "severity": str,        # "critical" | "warning" | "info"
    "is_active": bool
}

Key Logic:
State Machine: Each device has a state — UP, DOWN, DEGRADED (high latency), UNKNOWN
Hysteresis: Don't alert on single ping failure; require consecutive_failures (e.g., 2-3) before marking DOWN
Recovery Detection: Device must pass consecutive_successes (e.g., 2) before marking UP again
Latency Tracking: Record response time; flag DEGRADED if > threshold

ALERT TYPES:
| Type           | Channel       | Use Case                           |
| -------------- | ------------- | ---------------------------------- |
| **Immediate**  | Email         | Device goes DOWN                   |
| **Digest**     | Email (batch) | Daily/weekly summary of all issues |
| **Dashboard**  | Real-time SSE | Live status updates on web UI      |
| **Escalation** | Email + SMS   | Critical device down for > 15 min  |
